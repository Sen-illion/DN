# 云端图片存储改造方案（修改思路）

> 目标：建立开发者云端，图片直接上传到云存储，前端用 CDN URL 展示，减少本地缓存耗时，支持多人游玩。

---

## 一、当前架构与痛点

### 1.1 现有图片流

```
生图 API (云雾/Gemini 等)
    ↓ 返回 base64 或 URL
save_base64_image() → image_cache/xxx.png
    ↓ 返回 /image_cache/xxx.png
game_server 静态路由 /image_cache/<filename> → 读本地文件
    ↓
前端 http://127.0.0.1:5001/image_cache/xxx
```

### 1.2 依赖关系

| 环节 | 依赖 | 当前输入 |
|------|------|----------|
| **上一张图依赖**：下一张剧情图参考上一张 | 需要上一张图的 URL | `previousSceneImage.url` 支持 `/image_cache/` 或 `http(s)://` |
| **视觉裁剪**：配角初登场图裁单人 | 需要图片文件 | `Path` 本地路径，`_load_image_as_data_uri(path)` 读本地 |
| **配角建档** | 需要初登场图路径 | `scene_image_path` 本地路径，`shutil.copy2` + `get_character_bbox_and_crop` |
| **前端展示** | 需要可访问的 URL | `http://127.0.0.1:5001/image_cache/xxx` 或任意 URL |

### 1.3 痛点

- 本地缓存：每次生图都要先落盘到 `image_cache/`，再通过 Flask 路由返回
- 多人游玩：部署到云服务器后，`image_cache` 在服务器本地，前端访问需经服务器转发
- 扩展性：本地磁盘有限，无法利用 CDN 加速

---

## 二、目标架构

```
生图 API
    ↓
上传到云端（OSS/S3/R2）
    ↓ 返回公网 URL
前端直接使用 CDN URL
    ↓
上一张图依赖：云端 URL 已支持（api_providers 已有）
    ↓
视觉裁剪：云端 URL → 临时拉取 → 裁剪 → 上传裁剪结果到云端
    ↓
配角建档：存档中存云端 URL

可选：本地 image_cache 作为兜底（开发/降级）
```

---

## 三、改造范围与优先级

### 3.1 核心模块

| 模块 | 改动点 | 优先级 |
|------|--------|--------|
| **云存储抽象** | 新增 `src/image/cloud_storage.py`，统一上传接口 | P0 |
| **配置** | `.env` 新增云存储相关配置，`src/config.py` 读取 | P0 |
| **storage.py** | `save_base64_image` 支持「上传到云端」模式 | P0 |
| **api_providers.py** | 生图返回后调用云上传，返回云端 URL | P0 |
| **game_server.py** | `/image_cache/` 路由：云端 URL 直接返回；本地路径仍保留兜底 | P1 |
| **vision_ref_crop.py** | 支持「URL 输入」：先 fetch 到临时文件再处理 | P0 |
| **supporting.py** | `archive_supporting_role_first_appearance` 支持云端 URL 作为 `scene_image_path` | P0 |
| **game_server.py** | `_archive_supporting_roles_on_option_shown` 支持云端 URL | P0 |
| **前端 script-modular.js** | 图片 URL 处理：支持 `/image_cache/` 与云端 URL 并存 | P1 |

### 3.2 可选增强

| 项目 | 说明 |
|------|------|
| 预签名 URL | 私有桶时，前端用短期预签名 URL 访问 |
| 本地兜底 | 云存储未配置时，仍走 `image_cache` |
| 裁剪图上传 | 视觉裁剪结果也上传到云端，档案存云端 URL |

## 四、详细修改思路

### 4.1 新建云存储模块 `src/image/cloud_storage.py`

**职责**：统一上传接口，支持多种后端（阿里云 OSS、AWS S3、Cloudflare R2 等）。

**接口设计**：

```python
# 伪代码
def upload_image(data: bytes, key: str, content_type: str = "image/png") -> Optional[str]:
    """
    上传图片到云存储，返回公网 URL。
    :param data: 图片二进制
    :param key: 对象键（如 image_cache/xxx.png）
    :param content_type: MIME 类型
    :return: 公网 URL，失败返回 None
    """
    pass

def is_cloud_enabled() -> bool:
    """是否配置了云存储。"""
    pass
```

**实现建议**：
- 使用 `boto3` 兼容 S3（AWS S3、Cloudflare R2、MinIO）
- 阿里云 OSS 用 `oss2` 或 S3 兼容 endpoint
- 配置项：`CLOUD_STORAGE_PROVIDER`、`CLOUD_STORAGE_BUCKET`、`CLOUD_STORAGE_REGION`、`CLOUD_STORAGE_ACCESS_KEY`、`CLOUD_STORAGE_SECRET_KEY`、`CLOUD_STORAGE_ENDPOINT`（可选）、`CLOUD_STORAGE_CDN_URL`（可选，自定义域名）

### 4.2 配置扩展 `.env` + `src/config.py`

**新增环境变量**（示例）：


### 4.3 修改 `src/image/storage.py`

**`save_base64_image` 扩展**：

```python
# 伪代码
def save_base64_image(data_uri, prompt, cache_key_suffix=None) -> Optional[str]:
    # ... 解码 base64 ...
    
    if cloud_storage.is_cloud_enabled():
        key = f"{prompt_hash}.{image_format}"  # 或带 prefix
        url = cloud_storage.upload_image(image_data, key, content_type)
        if url:
            return url  # 直接返回云端 URL
        # 上传失败 fallback 到本地
    
    # 原有逻辑：保存到 image_cache
    return f"/image_cache/{prompt_hash}.{image_format}"
```

**要点**：云存储优先，失败时回退到本地；本地缓存 key 仍用 `prompt_hash` 保证一致性。

---

### 4.4 修改 `src/image/api_providers.py`

**生图返回**：所有返回 `base64` 或 `URL` 的路径，最终都经 `save_base64_image` 或等价逻辑处理。

- 若 `call_gemini_img2img`、`call_yunwu_image_api` 等内部已调用 `save_base64_image`，则只需保证 `save_base64_image` 支持云上传即可。
- 若有返回第三方 URL 的路径（如 DALL-E），需增加「下载 → 上传云端」逻辑，或统一走「上传后返回云端 URL」。

**参考图**：`previous_scene_image_path` 已支持 `http(s)://`，云端 URL 可直接用，无需改动。

---

### 4.5 修改 `src/characters/vision_ref_crop.py`

**问题**：`_call_vision_bbox`、`crop_image_by_bbox`、`get_character_bbox_and_crop` 均接收 `Path` 本地路径。

**方案**：增加「URL → 临时文件」的封装。

```python
def _resolve_image_path_or_url(path_or_url) -> Optional[Path]:
    """
    将本地路径或 HTTP URL 转为可读的 Path。
    URL 时：fetch 到临时文件，返回 Path。
    """
    if not path_or_url:
        return None
    s = str(path_or_url).strip()
    if s.startswith(("http://", "https://")):
        # 下载到 tempfile，返回 Path
        import tempfile
        import requests
        resp = requests.get(s, timeout=30)
        resp.raise_for_status()
        ext = ".png" if "png" in resp.headers.get("content-type", "") else ".jpg"
        tmp = tempfile.NamedTemporaryFile(suffix=ext, delete=False)
        tmp.write(resp.content)
        tmp.close()
        return Path(tmp.name)
    p = Path(s)
    return p if p.exists() else None
```

**`get_character_bbox_and_crop`**：入口处增加 `path_or_url` 支持，内部先 `_resolve_image_path_or_url`，再传给 `_call_vision_bbox` 和 `crop_image_by_bbox` 使用。裁剪结果可继续上传到云端（可选）。

---

### 4.6 修改 `src/characters/supporting.py`

**`archive_supporting_role_first_appearance`**：

- `scene_image_path` 支持：`/image_cache/xxx` 或 `https://xxx.oss.xxx/xxx.png`
- 若为 URL：先 `_resolve_image_path_or_url` 得到临时文件，再 `shutil.copy2` 到 `first_img_path`，后续 `get_character_bbox_and_crop` 用本地路径。
- 档案中 `first_img_path` 可改为存 URL（若裁剪结果也上传云端），或保持本地路径（兼容旧逻辑）。

---

### 4.7 修改 `game_server.py`

**`_archive_supporting_roles_on_option_shown`**：

- 当前仅接受 `scene_url` 以 `/image_cache/` 或 `image_cache/` 开头。
- 扩展：若 `scene_url` 以 `http://` 或 `https://` 开头，直接传给 `archive_supporting_role_first_appearance`，由 supporting 内部做 URL 解析。

```python
# 伪代码
if scene_url.startswith("/image_cache/") or scene_url.startswith("image_cache/"):
    local_path = Path(IMAGE_CACHE_DIR) / Path(scene_url).name
    # 原有逻辑
elif scene_url.startswith(("http://", "https://")):
    # 直接传 URL，supporting 内部会 fetch 到临时文件
    archive_supporting_role_first_appearance(game_id, arch, scene_url, prompt)
```

**`/image_cache/<filename>` 路由**：

- 若前端仍可能请求 `/image_cache/xxx`（如本地兜底），保留现有逻辑。
- 若云端 URL 已直接返回给前端，前端不再请求 `/image_cache/`，该路由可保留作兼容。

---

### 4.8 修改 `game-frontend/script-modular.js`

**`displaySceneImage`**：

- 当前会修复 `image_cache` 路径为 `http://127.0.0.1:5001/image_cache/xxx`。
- 若 `finalImageUrl` 已是 `http(s)://` 云端 URL，直接使用，无需修复。
- 逻辑：`if (finalImageUrl.startsWith('http://') || finalImageUrl.startsWith('https://'))` 则直接使用；否则按现有逻辑处理 `/image_cache/`。

**`preloadImage`**：支持任意 URL，无需改动。

---

### 4.9 配角档案中的图片路径

- **初登场图**：`first_img_path` 当前为本地绝对路径。
- **裁剪图**：`body_ref` 路径同理。
- **改造**：若裁剪结果上传云端，可存 `first_img_url`、`body_ref_url`；生图时仍用 `_ref_image_to_input`，其已支持 URL。

## 五、数据流示意（改造后）

### 5.1 剧情图生成

```
generate_scene_image()
    → 生图 API 返回 base64
    → save_base64_image()
        → 若云存储启用：upload_image() → 返回 https://cdn.xxx/xxx.png
        → 否则：保存到 image_cache → 返回 /image_cache/xxx.png
    → option_data.scene_image.url = 云端 URL 或 /image_cache/xxx
```

### 5.2 上一张图依赖（下一张剧情图）

```
previousSceneImage.url = https://cdn.xxx/prev.png
    → api_providers 中 previous_scene_image_path = 该 URL
    → _ref_image_to_input(URL) 已支持 URL，直接返回
    → call_gemini_img2img 传入参考图
```

### 5.3 配角初登场建档

```
notify-scene-displayed
    → scene_url = https://cdn.xxx/xxx.png
    → _archive_supporting_roles_on_option_shown 支持 URL
    → archive_supporting_role_first_appearance(scene_url, ...)
        → _resolve_image_path_or_url(scene_url) → 临时文件 Path
        → shutil.copy2 到 first_img_path（本地）
        → get_character_bbox_and_crop(first_img_path, ...)
            → 视觉模型 bbox → 裁剪 → 保存 body_ref
        → 可选：上传裁剪图到云端，档案存 URL
```

## 六、云存储选型建议

| 服务 | 适用场景 | 免费额度 |
|------|----------|----------|
| **Cloudflare R2** | 推荐，S3 兼容，无出口费 | 10GB 存储 |
| **阿里云 OSS** | 国内部署 | 有免费试用 |
| **AWS S3** | 海外部署 | 12 个月免费 |

---

## 七、实施顺序建议

1. **Phase 1**：云存储模块 + 配置 + `save_base64_image` 云上传
2. **Phase 2**：`vision_ref_crop` + `supporting` + `game_server` 支持 URL 输入
3. **Phase 3**：前端 URL 兼容 + 裁剪结果上传云端（可选）
4. **Phase 4**：测试、降级、文档

---

## 八、风险与回退

| 风险 | 应对 |
|------|------|
| 云存储故障 | 上传失败时 fallback 到本地 `image_cache` |
| 临时文件泄漏 | 使用 `tempfile`，用完后 `os.unlink` 或 `with` 上下文 |
| 跨域 | 云存储桶需配置 CORS，或通过 CDN 访问 |
| 成本 | 小规模游戏流量通常很低，可先用免费额度 |

---

## 九、总结

- **核心**：新增云存储模块，生图后统一上传，返回云端 URL。
- **兼容**：`previous_scene_image_path` 已支持 URL；视觉与建档需增加 URL 解析。
- **兜底**：未配置云存储时，仍走本地 `image_cache`。
- **玩家**：无需任何配置，所有图片由你的云端统一提供。

## 十、.env 配置示例（Cloudflare R2）

```env
# 云存储（可选，不配置则仍用本地 image_cache）
CLOUD_STORAGE_PROVIDER=r2
CLOUD_STORAGE_BUCKET=your-bucket-name
CLOUD_STORAGE_REGION=auto
CLOUD_STORAGE_ACCESS_KEY=your-r2-access-key
CLOUD_STORAGE_SECRET_KEY=your-r2-secret-key
CLOUD_STORAGE_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
# R2 必须配置此项才能返回公网 URL（在 R2 控制台开启「公开访问」后获得，或绑定自定义域名）
CLOUD_STORAGE_CDN_URL=https://pub-xxx.r2.dev
CLOUD_STORAGE_PREFIX=game-images/
```

**依赖**：`pip install boto3`
