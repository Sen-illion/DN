# DN 预生成机制效率实验结果（60s 下一次点击口径，post-fix，12v12）

## 实验目的

本实验不再把“首轮生成是否更快”作为主问题，而是聚焦预生成机制的真实目标：
当玩家正在阅读当前剧情时，系统是否能在后台提前生成后续内容，从而减少玩家**下一次点击**时的等待，并提高下一次点击直接拿到**真实剧情**而不是占位/兜底文本的概率。

## 实验设置

- 研究对象：DN Web 主链路
- 固定阅读间隔：60 秒
- 比较组：
  - `pregen off`：关闭预生成
  - `pregen on`：开启预生成
- 数据范围：仅使用主角图修复后的 post-fix 数据
- 合并样本：
  - `off` 共 12 局
  - `on` 共 12 局
- 主指标：`second_click_elapsed_s`
- 效果约束：第二次点击是否返回真实剧情，近似用 `is_placeholder == false` 判定

## 结果概览

### 1. 总体第二次点击延迟

- `off`：median = `0.017s`，mean = `0.018s`，p95 = `0.033s`
- `on`：median = `0.013s`，mean = `0.016s`，p95 = `0.032s`

按中位数计算，开启预生成后，第二次点击延迟相对下降约 `23.5%`（`0.017s -> 0.013s`）。

### 2. 真实剧情命中率

- `off`：`4 / 12`，`real_scene_rate = 0.333`
- `on`：`10 / 12`，`real_scene_rate = 0.833`

也就是说，在玩家等待 60 秒后再次点击时，开启预生成能把“直接进入真实剧情”的命中率从 `33.3%` 提高到 `83.3%`，提升了 `50` 个百分点。

### 3. 只看真实剧情样本时的延迟

- `off`：real-scene median = `0.021s`
- `on`：real-scene median = `0.013s`

在只比较真实剧情样本时，预生成仍然更快，中位数相对下降约 `38.1%`（`0.021s -> 0.013s`）。

### 4. 配对比较

在 12 对同 benchmark 的配对样本中：

- `on` 更快：`8` 对
- `off` 更快：`4` 对
- 平局：`0` 对

更关键的是，在 `off/on` 两边都返回真实剧情的 `4` 对可直接比较样本里：

- `on` 更快：`4 / 4`
- `off` 更快：`0 / 4`

这说明，在“双方都真正返回了可玩的剧情内容”这一更严格条件下，预生成的正向收益是稳定存在的。

## 结果解释

这组结果支持如下判断：

1. **预生成的核心价值不在于优化当前请求，而在于隐藏下一次点击前的等待。**
   当前实验口径与这一目标一致，因此结论比早期“首轮耗时”口径更有效。

2. **预生成不仅提升了速度，更重要的是提升了“下一次点击时可直接进入真实剧情”的概率。**
   如果只看时延，`off` 也可能很快，但其中相当一部分实际上是快速返回占位文本；这类“快”并不等价于体验提升。

3. **在真实剧情可比样本中，预生成同时带来了更高命中率和更低等待时间。**
   这意味着预生成机制不是单纯通过“更激进地返回兜底文本”来换取速度，而是在较多情况下真的把后续内容准备好了。

## 与前一轮 8v8 相比的变化

和上一轮 `8v8` 相比，这一轮 `12v12` 的主要变化是：

- 结论方向保持一致，没有翻转；
- `on` 的总体中位时延优势仍然存在；
- `on` 的真实剧情命中率优势进一步稳定在显著差距上；
- 新增样本表明，`off` 组中“快速但占位”的情况依然持续存在，因此不能把“快返回”直接当作体验改进。

## 当前可以下的结论

基于目前的 post-fix `12v12` 真实执行结果，可以较有把握地得出：

**当玩家以约 60 秒的节奏阅读当前剧情并进行下一次点击时，DN 的预生成机制能够显著提高下一次点击直接获得真实剧情的概率，并在可比条件下减少下一次点击等待时间。**

## 仍需保留的限制

1. `real_scene` 目前仍是启发式判定，而不是后端显式标签。
2. 虽然 `12v12` 已明显强于早期样本，但总体样本量仍不算特别大。
3. 目前只验证了 `60s` 这一档最接近稳定收益的阅读间隔；`30s/40s` 档此前仍表现不稳定，说明收益依赖于后台准备时间是否足够。
4. 当前还没有把“pregeneration hit / on-demand / fallback”作为后端显式事件写入日志，因此机理归因仍然有进一步增强空间。

## 建议在正文中使用的简短结论

在主角图修复后的 post-fix 条件下，我们将实验口径从“首轮生成速度”调整为“玩家阅读当前剧情后下一次点击的等待时间”。在 `60s` 阅读间隔、`12v12` 的真实执行样本中，开启预生成后，第二次点击延迟中位数由 `0.017s` 降至 `0.013s`，同时真实剧情命中率由 `33.3%` 提升至 `83.3%`。在双方都返回真实剧情的配对样本中，预生成组 `4/4` 更快。该结果说明，DN 的预生成机制确实更符合其设计初衷：它不主要优化当前请求，而是通过在玩家阅读期间后台准备后续内容，减少下一次点击等待，并提高玩家直接进入真实剧情的概率。
